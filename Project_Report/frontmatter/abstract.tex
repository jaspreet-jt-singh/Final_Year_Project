\chapter*{ABSTRACT}
\addcontentsline{toc}{chapter}{ABSTRACT}

\begingroup
\setstretch{1.15}

Manual food logging becomes difficult because the same small tasks are repeated after every meal: identifying each dish, estimating the serving, finding a matching nutrition entry, and entering the remaining items on the plate. Indian meals make this less direct because one image may contain rice, dal, chutney, curry, fried items, sweets, and beverages, often with regional names or household variations. This project reduces that effort through an image-based Indian food recognition system with nutrition-aware recommendations. The system accepts a food image, detects visible food items using a YOLO-based object detector, links detected labels to Indian nutrition records, estimates calories and macronutrients per 100 grams, and presents dietary suggestions through a web application.

The implemented prototype consists of a FastAPI backend, a Next.js frontend, a SQLite nutrition database built mainly from the Indian Nutrient Database, and a merged YOLO-format dataset with 72 canonical Indian food classes. Five source datasets were combined after cleaning spelling differences, regional terms, and duplicate labels that could otherwise create separate detector outputs for the same dish. Examples such as \code{idly} and \code{idli}, or \code{satham} and \code{rice}, were handled before training. The final balanced export contains 48,693 image-label pairs across training, validation, and test splits. Visual verification sheets confirmed usable samples for all 72 classes and identified a few annotation-level issues for future correction.

The final detector was trained using YOLO11s on the 72-class dataset. The best model achieved 0.830 mAP@50 and 0.692 mAP@50:95 on validation, and 0.820 mAP@50 and 0.680 mAP@50:95 on the held-out test split. The nutrition layer maps all 72 dataset classes to database entries through explicit semantic mappings and verified supplemental rows before fuzzy matching. This was added after early tests showed that name similarity alone could return a nutritionally wrong food. The backend includes endpoints for image analysis, nutrition validation, macro calculation, daily goals, health conditions, and recommendation generation, while the frontend supports upload, detection visualization, serving adjustment, macro tracking, and personalized guidance.
