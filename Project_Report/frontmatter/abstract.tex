\chapter*{ABSTRACT}
\addcontentsline{toc}{chapter}{ABSTRACT}

Manual food logging becomes difficult mainly because it repeats the same small tasks after every meal. The user has to identify each dish, estimate the serving, find a matching nutrition entry, and repeat the process for the remaining items on the plate. Indian meals make this task less direct because one plate may contain rice, dal, chutney, curry, fried items, sweets, and beverages, often with regional names or household variations. This project was developed to reduce that effort by building an image-based Indian food recognition system with nutrition-aware recommendations. The system takes a food image as input, detects visible food items through a YOLO-based object detector, links the detected labels to Indian nutrition records, estimates calories and macronutrients per 100 grams, and presents dietary suggestions through a web application.

The implemented prototype consists of a FastAPI backend, a Next.js frontend, a SQLite nutrition database built mainly from the Indian Nutrient Database, and a merged YOLO-format dataset with 72 canonical Indian food classes. Five source datasets were combined, but this was not a direct file merge. The class names had to be cleaned because spelling differences, regional words, and duplicate labels could create separate detector outputs for the same dish. Examples such as \code{idly} and \code{idli}, or \code{satham} and \code{rice}, were handled before training. The final balanced export contains 48,693 image-label pairs across training, validation, and test splits. Visual verification sheets were also prepared from actual dataset images. These sheets confirmed that all 72 classes had usable samples and also pointed out a few annotation-level issues that should be corrected in later iterations.

The final detector was trained using YOLO11s on the 72-class dataset. The best model achieved 0.830 mAP@50 and 0.692 mAP@50:95 on validation, and 0.820 mAP@50 and 0.680 mAP@50:95 on the held-out test split. The nutrition layer maps all 72 dataset classes to database entries through explicit semantic mappings and verified supplemental rows before fuzzy matching is used. This was added after early tests showed that name similarity alone could return a nutritionally wrong food. The backend includes endpoints for image analysis, nutrition validation, macro calculation, daily goals, health conditions, and recommendation generation. The frontend supports image upload, detection visualization, serving adjustment, macro tracking, and personalized guidance. The report documents the design decisions, implementation work, validation results, limitations, and future improvements of the system.
